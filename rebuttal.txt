Q1.  Why were experiments limited to n = 3 ? Can you show n = 5 (or n = 10) ?
================================================================================

The choice n = 3 in the camera-ready version was made for figure clarity,
not because of any conceptual or algorithmic limit. We have rerun the
per-round-regret experiment at n = 5 with K_max = 4 attacker types,
T = 6000 rounds and 20 random seeds; see
figures/per_round_regret_n5_nonuniform.png. The qualitative picture from
n = 3 carries over without modification:

  * Per-round regret spikes at every type-reveal round and decays inside
    each epoch at the O(t^{-1/2}) rate that Hedge predicts on the enlarged
    expert set E(C_t).
  * The rolling mean returns close to zero in every epoch, and converges
    visibly to zero in the long final epoch (length 3200), giving direct
    empirical support for the no-regret statement at n = 5.

For n = 5, K = 4 the EXACT vertex enumeration we use in the released code
becomes expensive: we measured (single laptop core, numpy)

        K_after = 1 :   80 ms,    |E| =   148
        K_after = 2 :  6.13 s,    |E| =  1578
        K_after = 3 : 77.68 s,    |E| =  6057
        K_after = 4 :  348.65 s,  |E| = 13794

A run of T = 6000 rounds with all four discovery events would therefore
spend ~430 s in compute_extreme_points alone, plus T * |E_max| = 8.3e7
expert evaluations in the per-round Hedge update, which is what made our
camera-ready experiments stop at n = 3.

For the n = 5 experiment we therefore replaced the exhaustive enumeration
with an APPROXIMATE construction of E(C ; eps): we draw M = 2000 coverage
vectors from a Dirichlet(1) over the (n-1)-simplex (plus the n simplex
corners), and deduplicate by best-response signature against the current
catalogue. Each surviving sample is a representative interior point of one
cell of the partition; the resulting set is an eps-cover with eps = O(1/sqrt M).

The proof of the main theorem is stated for an arbitrary eps-cover (Lemma
4.3 of Balcan-Blum-Haghtalab-Procaccia 2015), so the regret bound carries
over verbatim with the standard additive eps * T term, which is negligible
at our settings (eps approx 0.022, eps * T approx 130 versus a sqrt-T budget
of ~300). The figure is generated with this approximate cover.

For n = 10, both the exact arrangement (C(190, 9) ~ 3.6e12 subsets) and
the n^K = 10^4 cell count are out of reach with the present code; the
sampling construction above is the natural approach there and is
implemented and tested at n = 5 here.

================================================================================
Q2.  Runtime cost of E(C, eps) per discovery round, scaling with n and K_max
================================================================================

The set E(C ; eps) is the vertex set of the arrangement induced by the
simplex boundaries (n hyperplanes) plus, for each attacker type alpha in
the catalogue, its C(n, 2) pairwise best-response indifference hyperplanes.
With |C| = K, the number of defining hyperplanes is

        H(n, K) = n + K * n(n-1)/2 .

The exact vertex enumeration in algorithm.py intersects every (n-1)-subset
of these hyperplanes:

        T_exact(n, K) = O( C(H(n,K), n-1) * (n-1)^3 ) ,

where (n-1)^3 is the cost of one linear solve. K appears inside a binomial
coefficient of order n - 1, hence

        T_exact(n, K) = O( K^{n-1} * poly(n) )      (fixed n)
        T_exact(n, K) = exp( O(n log K) )           (fixed K, growing n).

This matches Lemma 4.3 of Balcan et al. (2015): |E(C ; eps)| is polynomial
in K for fixed n.

EMPIRICAL TIMINGS (single laptop core, numpy, mean over 20 seeds):

  Exact enumeration, n = 5:
        K = 1 :     80 ms      ( |E| =   148 )
        K = 2 :   6,130 ms     ( |E| =  1578 )
        K = 3 :  77,680 ms     ( |E| =  6057 )
        K = 4 : 348,650 ms     ( |E| = 13794 )

  Sampled eps-net (M = 2000), n = 5:
        K = 1 :    4.8 ms      ( |E| =   3.8 )
        K = 2 :    9.1 ms      ( |E| =   9.8 )
        K = 3 :   13.4 ms      ( |E| =  20.7 )
        K = 4 :   17.6 ms      ( |E| =  38.3 )

The sampled construction is ~20,000x faster at K = 4 and produces an |E|
that is roughly the number of OCCUPIED best-response cells (at most n^K =
625 in this setting, typically far fewer).  Crucially, a discovery round
happens at most K_max times over the entire run, so the AMORTIZED
per-round cost of E(C, eps) is

        O( T_E(n, K) * K_max / T )   ->   0   as T -> inf,

i.e. the runtime of E(C, eps) does not affect the asymptotic per-round
cost, which is dominated by the O(|E|) Hedge update.

Two practical scaling strategies for n >> 5 :

  (a) Sampling, as used in the new figure: M Dirichlet samples from the
      simplex, deduplicated by best-response signature.  Cost
      O( M * K * n ) per discovery round, independent of dim.
  (b) Reverse-search vertex enumeration (Avis-Fukuda style), which runs
      in time linear in the output |E| rather than in the binomial.

Both preserve the regret bound because the proof uses only that E is a
finite eps-cover of the cell partition.

================================================================================
Q3.  Intuition for the regret curves when epoch sizes are not uniform
================================================================================

The per-epoch regret bound from the proof has the form

        R(epoch i)  <=  c * sqrt( ell_i * log |E(C_i)| ) ,

where ell_i is the length of epoch i and |E(C_i)| is the expert-set
cardinality during it. Two intuitions follow.

  (i)  Within an epoch, per-round regret decays like 1/sqrt(t_within_epoch),
       and the AVERAGE per-round regret over the epoch is
       c * sqrt( log |E_i| / ell_i ) . A SHORT epoch shows a high plateau
       in the rolling per-round-regret curve (Hedge has not had time to
       converge before a new type forces a restart), and a LONG epoch
       shows a clean decay toward zero. Total regret is dominated by the
       longest epochs since sum_i sqrt(ell_i) is concave in ell_i.

  (ii) The bound depends on epoch lengths only through their SQRT, not
       their values. So the worst case for total regret is K_max EQUAL
       epochs of length T / K_max, which gives sum_i sqrt( T / K_max ) =
       sqrt( T * K_max ). By Cauchy-Schwarz, any non-uniform schedule
       with the same T yields a strictly smaller upper bound. In other
       words: non-uniform epoch sizes are FAVORABLE to the algorithm
       relative to the worst case used in the regret theorem.

The new figure (epoch lengths (300, 800, 1700, 3200) summing to T = 6000)
confirms both intuitions. The first epoch (ell_1 = 300) shows an elevated
plateau around 0.05-0.06 because Hedge has only 300 rounds to run on a
trivial expert set before a new reveal arrives. The second and third
epochs (ell_2 = 800, ell_3 = 1700) show progressively cleaner decay.
The last epoch (ell_4 = 3200) shows the rolling-mean per-round regret
converging visibly to zero, modulo the small spike at the reveal itself.
The cumulative regret over the run was well below the bound that the
worst-case (uniform) schedule sqrt(T * K_max) ~ 155 would predict.

Q4.  Formal definition of the Polynomial-Weights distribution q_t
================================================================================

Apologies for the omission. Inside epoch i the algorithm runs the
Polynomial-Weights / Hedge subroutine over the finite expert set
E_i = E(C_i ; eps) , with cardinality N_i = |E_i|. Let
loss^{(t)} : E_i -> [0, 1] be the bounded loss observed at round t of the
epoch (the negative defender payoff, normalized into [0, 1] using the
[-1, 1] payoff range). For each expert p in E_i we maintain the
cumulative loss

        L^{(t)}(p)  =  sum_{s = 1}^{t-1} loss^{(s)}(p) ,

and the Polynomial-Weights distribution played at round t is

                    exp( - eta_t * L^{(t)}(p) )
        q_t(p)  =  ----------------------------------                   (*)
                    sum_{p' in E_i} exp( - eta_t * L^{(t)}(p') ),

with the anytime learning-rate schedule

        eta_t  =  sqrt( log N_i / t ) .

This is exactly the Hedge schedule of Cesa-Bianchi-Mansour-Stoltz (2007)
without horizon, and it gives the anytime regret bound that the proof of
the main theorem requires:

   sum_{t=1}^{ell_i} ( <q_t, loss^{(t)}> - loss^{(t)}(p*) )
                          <=  c * sqrt( ell_i * log N_i )

uniformly in ell_i, for any fixed comparator p* in E_i.  The played
coverage p_t in Algorithm 1 of the report is sampled from q_t in (*),
i.e. p_t ~ q_t over E_i. This matches the implementation in
code/algorithm.py (class HedgeLearner): the cumulative-loss state is kept
in log space and eta_t is recomputed each round as sqrt( log N_i / t ).

================================================================================
Q5.  Extension to imperfect-information / bandit feedback
================================================================================

In the bandit setting the defender plays p_t but only observes its OWN
realized payoff (or even just whether an attack succeeded), not the type
of the attacker. This breaks two specific places in Algorithm 1:

  (a) Discovery test. We can no longer detect a never-before-seen type
      just by reading off type labels.
      Replacement: cluster observed loss-vectors over a sliding window.
      Whenever the empirical mean loss-vector is incompatible (in a
      chi-square or KL sense) with mixtures over the current catalogue,
      declare a new type and enlarge C. This converts type discovery into
      a CHANGE-POINT detection problem on the loss process.

  (b) Hedge update. The full-information loss vector
      (loss^{(t)}(p) for p in E(C_t)) is not observed; only
      loss^{(t)}(p_t) is.
      Replacement: use Exp3 with importance-weighted estimators
      hat-loss^{(t)}(p) = loss^{(t)}(p_t) * 1{p = p_t} / q_t(p_t) .
      The same anytime learning-rate schedule extends directly, with
      regret bound O( sqrt(T * N_i * log N_i) ) per epoch (a sqrt(N_i)
      factor worse than full-information).

A complete extension theorem would then have the form

        Regret_bandit(T)  =  O( sqrt(T * K_max * |E_max| * log |E_max|) )
                             + O( T_detect * K_max ),

where |E_max| = max_i |E(C_i)| and T_detect is the worst-case detection
delay from (a). The K_max-discovery-events structure of GROW-CATALOGUE is
preserved; only the full-information Hedge box and the type-detection box
are swapped for their bandit-feedback analogues. We agree with the
reviewer that this is an important and natural direction; a careful
treatment with detection-delay analysis is left to follow-up work.
